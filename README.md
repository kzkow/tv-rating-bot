# tv-rating-bot

Присылает в Telegram торговые аномалии MOEX (Mega Alerts) по списку акций, фьючерсам на них и макро-фьючерсам. В сообщении по акции —
текущая «Общая оценка» теханализа TradingView на 1 день, в скобках — на 1, 2 и 4 часа:

```
27/10 SBER: Перевес покупок, Крупные покупки
Оценка: покупать (1 покупать, 2 нейтрально, 4 покупать)
```

Оценку бот не опрашивает по расписанию: запрашивает её один раз за запуск и только когда есть что отправить.
Данные — из `scanner.tradingview.com` (то же, что показывает страница «Теханализ»); без подписки они с задержкой
15 минут. Если TradingView недоступен, алерт приходит без строки оценки. Список бумаг — `TICKERS` в `bot.py`.

До 23.10.2026 бот ещё каждые 5 минут опрашивал оценку и присылал её смены («SNGSP: Покупать → Продавать») —
это убрано.

## Настройка

1. Создать бота в @BotFather, получить токен.
2. Написать боту `/start`, открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять `message.chat.id`.
   Для канала: добавить бота админом, chat_id — `@имя_канала`.
3. Залить репозиторий на GitHub (публичный — в приватном не хватит бесплатных минут).
4. Settings → Secrets and variables → Actions → New repository secret: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
5. Actions → TradingView rating → Run workflow с галочкой «Прислать сводку» — придёт сводка оценки по всем бумагам.
6. Свой cron GitHub исполняет раз в 3–4 часа, поэтому workflow запускает внешний планировщик (cron-job.org):
   `POST https://api.github.com/repos/kzkow/tv-rating-bot/actions/workflows/rating.yml/dispatches`,
   тело `{"ref":"main"}`, заголовки `Authorization: Bearer <токен>`, `Accept: application/vnd.github+json`.
   Токен — fine-grained, только этот репозиторий, право Actions: Read and write.

## Mega Alerts (MOEX ALGOPACK)

`alerts.py` присылает в тот же чат торговые аномалии MOEX («Mega Alerts», тариф ALGOPACK Promo) по тем же бумагам из `TICKERS`.

- Секрет `MOEX_ALGOPACK_TOKEN` — API-ключ из https://data.moex.com/personal-account. Без него шаг пропускается.
- Одно сообщение на бумагу — дата (дд/мм), тикер и причины (`27/10 SBER: Перевес покупок, Крупные покупки (07:21, цена +0,44%)`), последней строкой — оценка
  TradingView на 1 день и 1/2/4 часа на момент отправки (для алертов «С опозданием» и «За вчера» — тоже текущая).
- В скобках — минута алерта и как изменилась цена за неё: закрытие минуты к закрытию предыдущей минутной свечи (если
  её нет — к открытию минуты). Один раз на минуту, после её последнего типа: в сообщении бывают алерты нескольких минут. Свечи — из apim по тому же ключу (без
  задержки, в отличие от анонимного ISS); сбой — сообщение уходит без изменения цены.
- Не присылаются «Аномальный объём» (`vol_99_9_pctl`) и «Рекорд объёма за 90 дней» (`vol_max`): общий объём без
  направления сделок. Список — `SKIPPED_TYPES` в `alerts.py`.
- Каждый тип по бумаге — не чаще раза в 30 минут (скользящее окно от последнего присланного): повторы внутри окна не приходят
  («Максимум цены за 90 дней» срабатывает каждую минуту, пока цена обновляет максимум).
- Первый запуск (и первый после смены ключа или перерыва больше суток) ничего не присылает — запоминает уже вышедшие алерты.
- Если apim недоступен 3 запуска подряд — одно сообщение «недоступны», после восстановления — «снова работают».
- **Фьючерсы** (срочный рынок, `fo`) — только макро: вечные доллар (USDRUBF), юань (CNYRUBF) и золото (GLDRUBF),
  нефть Brent (BR), индексы Мосбиржи (MIX) и РТС (RTS). Фильтр — по базовому активу (`FUTURES` в `alerts.py`),
  поэтому смена контракта при экспирации (MXZ6 → MXH7) ничего не ломает. Формат — `02/11 USDRUBF (доллар): Перевес продаж`,
  ссылка на контракт в Т-Инвестициях, без кнопок. Оценка TradingView — только дневная (часовых для фьючерсов
  сканер не отдаёт) и только если контракт там есть: символ с полным годом, `RUS:BRZ2026`; вечных USDRUBF, CNYRUBF,
  GLDRUBF в TradingView нет. Только у фьючерсов есть «Резкий рост / падение
  открытого интереса» — крупно открыли или закрыли позиции. Повторы, «С опозданием» и пропуск типов без направления —
  как у акций. Сбой срочного рынка не задерживает акции и не шлёт «недоступны»: его алерты придут следующим запуском.
  По валютному рынку (`fx`) Mega Alerts пусты.
- **Фьючерсы на акции** из `TICKERS` — только ближайший квартальный контракт: `03/11 SRZ6 (SBER): Крупные покупки`.
  Экспирация — третья пятница марта, июня, сентября и декабря; в день экспирации приходит ещё истекающий контракт,
  со следующего дня — следующий (SRZ6 → SRH7). Вечный SBERF и дальние контракты не присылаются. Актив фьючерса
  MOEX иногда называет иначе, чем акцию (SBER — SBRF, NVTK — NOTKM): `SHARE_ASSETS` в `alerts.py`. Как у макро:
  без кнопок, дневная оценка самого фьючерса (`RUS:SRZ2026`). На 03.11.2026 в TradingView есть фьючерсы на 13 акций
  из 25: AFLT, GMKN, LKOH, MOEX, MAGN, MTSS, NLMK, PHOR, ROSN, SNGSP, SBERP, SBER, TRNFP; по остальным оценки нет.
- Сертификат apim выпущен НУЦ Минцифры, его корня нет в стандартных хранилищах: он лежит в `certs/russian_trusted_root_ca.pem`
  (https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt, отпечаток сверяется в коде) и используется только для apim.
- Данные MOEX нельзя передавать третьим лицам, а репозиторий публичный: в `alerts_state.json` лежат только HMAC-хэши
  уже отправленных алертов, в логах Actions — только счётчики.

## Кнопки «Купить» и «Продать»

Под каждым сообщением Mega Alerts — кнопки «Купить» и «Продать» (1 лот по рынку),
`callback_data` вида `buy:SBER` / `sell:SBER`. Сводка и сообщения о недоступности Mega Alerts — без кнопок.
Сам бот кнопки не обрабатывает:
нажатие принимает обработчик в Telegram Serverless (проект tv-bot-serverless), а заявку выставляет
приватный репозиторий с токеном брокера. В этом публичном репозитории ничего, связанного с торговлей, не хранится.

## История сообщений

Всё, что бот отправил в Telegram (алерты, сводка, «недоступны»), сохраняется в приватный репозиторий `kzkow/tv-history`:
строка JSON на сообщение в `alerts/<дата МСК>.jsonl` — время, `message_id`, текст. Пишут последние шаги workflow,
в этом репозитории и в логах текстов нет. Секрет `HISTORY_TOKEN` — fine-grained token с доступом только
к tv-history, права *Contents: Read and write*. Без него алерты идут как обычно, а шаг истории падает
(не роняя запуск).

## Локально

```bash
python bot.py                     # сводка оценки; без переменных TELEGRAM_* — печать в консоль
# Mega Alerts; без TELEGRAM_* — печать в консоль. Состояние — во временный файл:
# alerts_state.json в репозитории ведёт workflow, локальные правки в нём спрятали бы алерты в Telegram.
MOEX_ALGOPACK_TOKEN=... ALERTS_STATE_FILE=/tmp/alerts_state.json python alerts.py
```
